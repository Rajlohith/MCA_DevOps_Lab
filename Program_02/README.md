# Program 2 – Build a Multi-Stage Docker Container

## Description

The objective of this problem is to develop a multi-stage Dockerfile. The multi-stage build separates the application build environment from the production environment, helping optimize the Docker image, improve build efficiency, and streamline the deployment process.

The application is a Node.js Express application that runs on port `3000`.

## Project Files

```text
program-2/

├── Dockerfile
├── package.json
├── package-lock.json
├── node_modules/
└── src/
    └── index.js
```

### Dockerfile Instructions

* `FROM` – Uses Node.js 20 Alpine as the base image.
* `FROM ... AS builder` – Creates the first stage of the multi-stage Docker build.
* `WORKDIR` – Sets `/app` as the working directory inside the container.
* `COPY` – Copies the package files and application source code into the container.
* `RUN` – Installs the Node.js dependencies using `npm install`.
* `COPY --from=builder` – Copies the required files from the builder stage into the production stage.
* `EXPOSE` – Documents that the application uses port `3000`.
* `CMD` – Starts the Node.js Express application.

## 1. Build the Docker Image

Open the terminal in the project directory and execute:

```bash
docker build -t program-2 .
```

Here:

* `docker build` – Builds a Docker image.
* `-t program-2` – Gives the image the name `program-2`.
* `.` – Uses the current directory as the build context.

During the build process, Docker executes the two stages defined in the Dockerfile.

The first stage is the **Build Stage**:

```dockerfile
FROM node:20-alpine AS builder
```

This stage:

* Creates a Node.js 20 Alpine environment.
* Sets `/app` as the working directory.
* Copies `package.json` and `package-lock.json`.
* Installs the required dependencies using `npm install`.
* Copies the application source code.

The second stage is the **Production Stage**:

```dockerfile
FROM node:20-alpine
```

This stage creates the final Docker image and copies the required files from the builder stage.

To verify the image:

```bash
docker images
```

The image should appear with the name:

```text
program-2
```

---

## 2. Run the Docker Container

Run the container using:

```bash
docker run -it -p 3000:3000 program-2
```

Here:

- `-it` – Runs the container in interactive mode with a terminal attached.
* `-p 3000:3000` – Maps port `3000` of the host machine to port `3000` inside the container.
* `program-2` – Specifies the Docker image to use.

To check whether the container is running:

```bash
docker ps
```

The container should appear with port mapping similar to:

```text
0.0.0.0:3000->3000/tcp
```

## 9. Understanding the Multi-Stage Dockerfile

The Dockerfile contains two stages.

### Stage 1 – Build Stage

```dockerfile
FROM node:20-alpine AS builder

WORKDIR /app

COPY package*.json ./

RUN npm install

COPY . .
```

The first stage creates the build environment.

The command:

```dockerfile
FROM node:20-alpine AS builder
```

uses Node.js 20 Alpine as the base image and gives this stage the name `builder`.

The working directory is set to:

```text
/app
```

The package files are then copied:

```dockerfile
COPY package*.json ./
```

The application dependencies are installed using:

```dockerfile
RUN npm install
```

Finally, the application source code is copied:

```dockerfile
COPY . .
```

### Stage 2 – Production Stage

```dockerfile
FROM node:20-alpine

WORKDIR /app

COPY --from=builder /app/package*.json ./

COPY --from=builder /app/node_modules ./node_modules

COPY --from=builder /app/src ./src

EXPOSE 3000

CMD ["node", "src/index.js"]
```

The second stage creates the final production image.

The command:

```dockerfile
COPY --from=builder
```

copies files from the first stage into the second stage.

The package files are copied using:

```dockerfile
COPY --from=builder /app/package*.json ./
```

The installed Node.js dependencies are copied using:

```dockerfile
COPY --from=builder /app/node_modules ./node_modules
```

The application source code is copied using:

```dockerfile
COPY --from=builder /app/src ./src
```

The application port is documented using:

```dockerfile
EXPOSE 3000
```

Finally, the Express application is started using:

```dockerfile
CMD ["node", "src/index.js"]
```

## 10. Advantages of Multi-Stage Docker Builds

A multi-stage Dockerfile separates the build process from the final production environment.

The general process is:

```text
Build Stage
     |
     | Install dependencies
     | Copy application
     |
     v
Production Stage
     |
     | Copy required files
     | Start application
     |
     v
Final Docker Image
```

The advantages include:

* Separation of build and production stages.
* Better organization of the Dockerfile.
* Reduced unnecessary files in the final image.
* Use of a lightweight Alpine Linux base image.
* Improved build and deployment process.
* Suitable structure for CI/CD pipelines.
* Can be used with container orchestration platforms such as Docker Compose and Kubernetes.
